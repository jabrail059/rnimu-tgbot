# Патанатомия: Telegram bot + Mini App

Подписка на 30 дней. Контент выдаётся API только после серверной проверки подписанной Telegram `initData` и активной подписки.

## Платежи

Основной поток — YooKassa API v3. Бот создаёт redirect-платёж с `capture=true`; checkout ЮKassa показывает все включённые в кабинете методы (в том числе карту и СБП). Браузерное возвращение с checkout **не** выдаёт доступ. Только `POST /api/payment/webhook`, сверенный с `GET /payments/{id}` в YooKassa, меняет статус и продлевает подписку.

Временный Quickpay оставлен за `ENABLE_LEGACY_YOOMONEY=true`. Не включайте его после приёмочного теста YooKassa. В личном кабинете YooKassa настройте HTTPS URL `https://<домен>/api/payment/webhook` для событий `payment.succeeded`, `payment.waiting_for_capture`, `payment.canceled`.

## Локальный запуск

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
# заполните .env настоящими значениями
python main.py
```

`PUBLIC_BASE_URL` обязан быть публичным HTTPS URL. Для разработки используйте HTTPS-туннель. Не коммитьте `.env`, секрет YooKassa или токен Telegram.

## Ubuntu deployment

1. Создайте системного пользователя `pathology`, разверните проект в `/opt/rnimu-tgbot`, создайте venv и каталог `data`, принадлежащий этому пользователю.
2. Скопируйте `.env.example` в `/etc/pathology-bot.env`, укажите реальные секреты и установите права `sudo chmod 600 /etc/pathology-bot.env`.
3. Замените домен и пути сертификатов в `deploy/nginx.conf`, включите конфигурацию nginx и получите TLS-сертификат.
4. Установите `deploy/pathology-bot.service` в `/etc/systemd/system/`, затем выполните:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pathology-bot
sudo nginx -t && sudo systemctl reload nginx
sudo journalctl -u pathology-bot -f
```

For consistent SQLite backups (including WAL data), install and enable the backup timer:

```bash
sudo install -d -o pathology -g pathology -m 700 /var/backups/pathology-bot
sudo cp deploy/pathology-backup.service deploy/pathology-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pathology-backup.timer
```

The template retains 14 daily files. Copy backups off-host; a backup on the same disk does not protect against disk loss.

Не открывайте порт 8000 наружу: сервис слушает только `127.0.0.1`. `TRUST_PROXY_HEADERS=true` допустим только с приложенной конфигурацией nginx и таким сетевым ограничением.

## Перед production

- Проверьте `https://<домен>/healthz`.
- В YooKassa включите методы оплаты (карта, СБП и нужные дополнительные) и укажите webhook URL/события.
- Проведите тестовый платёж: в БД должна появиться запись `provider=yookassa`, затем `succeeded`; подписка должна продлиться ровно один раз при повторной доставке webhook.
- Проверьте, что возврат со страницы оплаты без `payment.succeeded` не открывает контент.
- Проверьте `/start`, покупку, истечение подписки, а также логи `journalctl`.
- После приёмки установите `ENABLE_LEGACY_YOOMONEY=false` и удалите legacy-ключи из `/etc/pathology-bot.env`.

## Управление курсом

Требуется Python 3.11 или новее. После обновления установите зависимости из `requirements.txt` (добавлен Pillow) и перезапустите сервис. При старте автоматически выполняется повторяемая миграция № 2: добавляются `categories`, `materials`, `material_images`. Существующие пользователи, платежи и даты подписок сохраняются. Каталог начинает работу пустым; прежние демонстрационные заглушки из `app/content.py` больше не выдаются API.

1. Отправьте боту `/id`, чтобы узнать свой числовой Telegram ID.
2. Укажите `ADMIN_IDS=123456789,987654321` в `.env` или `/etc/pathology-bot.env` и перезапустите бота. Пустое значение отключает админку. Используйте ID, а не `@username`.
3. Откройте приложение из личного чата с ботом → **Управление** → **+ Раздел**.
4. В разделе нажмите **+ Материал**, заполните название и текст, сохраните. Затем выберите фотографии; можно загрузить несколько за один раз. Они появятся в порядке загрузки.
5. Материалы становятся доступны подписчикам сразу после сохранения. Через админку можно редактировать текст, переименовывать разделы, удалять отдельные фото, материалы и разделы. При удалении раздела удаляются все его материалы и фотографии; интерфейс запрашивает подтверждение.

Администратор читает и редактирует материалы без подписки. Права проверяются сервером по подписанному Telegram `initData` и `ADMIN_IDS` на каждом запросе. Таблица `admins` намеренно не создаётся: ENV остаётся единственным источником прав, без рассинхронизации с базой. После изменения ENV нужен перезапуск процесса.

При обновлении ранней версии админки сохраняются существующие разделы, материалы и фото. Старые имена настроек `ADMIN_USER_IDS` и `MEDIA_DIR` поддерживаются, если соответствующие новые переменные не заданы; явно пустое `ADMIN_IDS` отключает админку. Если путь не указан и существует только старый каталог `data/media`, используется он. Если имеются оба каталога, укажите нужный через `MEDIA_PATH`. Старая таблица `admins` остаётся в базе, но не выдаёт права. Фото с прежними UUID-именами `.jpg`, `.png`, `.webp` читаются и выдаются с водяными знаками. Не заменяйте рабочую базу или каталог фотографий файлами из архива с кодом.

В редакторе материала можно выбрать другой раздел. Сохранены лимиты ранней админки: название раздела до 200 символов, название материала до 300, текст до 200 000.

Бот поддерживает `/start`, `/menu`, `/id`, кнопки оплаты, открытия приложения и информации о курсе. `/menu` показывает актуальную дату окончания подписки по московскому времени. Автор — `@eucliris`. Цена и срок в боте и Mini App берутся из настроек.

## Фотографии и защита

`MEDIA_PATH=data/material_images` — приватный каталог, находящийся вне `web/`. Он должен быть доступен для записи пользователю сервиса. При изменении пути за пределы `data/` скорректируйте `ReadWritePaths` в systemd. **Не добавляйте для него nginx alias или StaticFiles.** Для собственного пути также добавьте исключение в `.gitignore`.

Принимаются неподвижные JPEG, PNG и WebP до 10 МиБ и 20 мегапикселей. Сервер проверяет содержимое, применяет EXIF-ориентацию, удаляет метаданные (включая GPS), уменьшает длинную сторону до 4096 пикселей и сохраняет JPEG под случайным именем. Неподдерживаемые форматы и повреждённые файлы отклоняются. Сохраняйте исходники у автора отдельно: загруженный файл нормализуется.

- Разделы, тексты и изображения выдаются только авторизованным подписчикам или администраторам. Имя файла не попадает в клиентский JSON. `/api/images/{id}` требует заголовок авторизации; открытие адреса без него не даёт фото.
- Каждое выдаваемое фото содержит повторяющийся водяной знак `@eucliris / ID …`, нанесённый сервером. Изображение рисуется на Canvas, временный Blob URL освобождается. В галерее работают свайпы, кнопки и клавиши стрелок.
- Ответы API имеют `Cache-Control: private, no-store`, не сохраняются в localStorage, IndexedDB или Service Worker. Выдача фото ограничена 60 запросами в минуту на пользователя; лимит хранится в памяти одного процесса.
- Копирование, контекстное меню и перетаскивание блокируются в читательском материале; поля администратора остаются пригодны для ввода и вставки. Печать скрывает приложение.
- При `blur`, `visibilitychange`, `pagehide` и Telegram `deactivated` приложение скрывается, текст читателя и Canvas очищаются. При возвращении проверяется доступ. Истечение подписки также запускает повторную проверку.

**Абсолютной защиты от скриншотов в Mini App нет.** В [документированном API Telegram Mini Apps](https://core.telegram.org/bots/webapps#events-available-for-mini-apps) есть события активности, но нет метода запрета системных снимков экрана. Canvas и блокировки браузера можно обойти; авторизованный пользователь технически может сохранить уже полученные данные или сфотографировать экран. Водяные знаки повышают стоимость такого копирования и позволяют связать опубликованное фото с аккаунтом. Блокировка клавиши PrintScreen — только дополнительная мера, не гарантия для ОС или телефона.

При обновлении nginx используйте текущий `deploy/nginx.conf`: лимит тела увеличен до 10 МиБ, CSP приходит из приложения и разрешает Blob-фото. `X-Frame-Options: SAMEORIGIN` убран, чтобы приложение открывалось в Telegram Web.

## Резервные копии материалов

Существующий `pathology-backup.timer` сохраняет **только SQLite**, включая тексты и ссылки на фото. Для полного восстановления нужна также копия `MEDIA_PATH`. Делайте согласованный снимок базы и каталога фотографий при остановленном сервисе либо средствами снимков файловой системы. Восстанавливайте их вместе, сохраняя имена файлов и права пользователя `pathology`; храните копии вне сервера. Перед первым запуском новой версии сохраните текущую базу и её WAL средствами SQLite backup API.

## Проверки

```bash
.venv/bin/python -m pip install pytest
.venv/bin/python -m pytest -q
.venv/bin/python -m compileall -q main.py app
```

Тесты используют временные базы и подменяют YooKassa: реальных платежей и сообщений Telegram нет. Проверяются миграция старой базы, права доступа, CRUD, лимиты и очистка фото, водяные знаки, истечение подписки и идемпотентность webhook. Браузерный тест дополнительно проверяет работу админки, загрузку нескольких фото, Canvas, свайп, скрытие при потере фокуса, возврат и отказ доступа после отключения подписки. Он использует уже установленные Firefox и geckodriver и пропускается, если они отсутствуют. Пути можно задать через `FIREFOX_BINARY` и `GECKODRIVER_BINARY`.

Перед публикацией проверьте на реальных клиентах Telegram Android/iOS/Desktop: открытие приложения, системный выбор фото, свайпы, сворачивание/возврат, подписку и тестовый платёж YooKassa. Автотесты не обращаются к рабочему боту или магазину.
